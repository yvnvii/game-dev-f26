⏺ I made the fix. python -m pytest -q gives 23 passed in 0.71s (22 existing
  tests plus the new one). The diff is shown above. Nothing is committed, and I
  didn't touch results/, suite.json, RULES or build_prompt.

  1. c4d/model_player.py: the default max_output_tokens is now 4096. choose()
     now also returns "finish_reason", taken from
     resp.candidates[0].finish_reason as its enum name (e.g. "MAX_TOKENS"). If a
     reply has no candidates or no finish reason, it is None, so a missing
     value can't crash a turn.
  2. c4d/runner.py: finish_reason is now recorded on both kinds of illegal trace
     event (no MOVE line found, and a move the engine rejected) and on accepted
     model moves.
  3. scripts/evaluate.py: there is a new --max-output-tokens option
     (default 4096). It is passed to ModelPlayer and saved in meta, so each
     summary.json and each trace's start event records which limit was used.
  4. tests/test_runner.py: the new test is test_truncated_reply_without_move_lin
     e_is_illegal_and_traced_with_finish_reason, with a docstring citing the
     2026-11-08 run. The scripted model first sends a cut-off reply with no MOVE
     line and finish_reason "MAX_TOKENS", then sends B2. The test checks that:
     - this counts as exactly one illegal attempt;
     - the illegal event carries "MAX_TOKENS";
     - the next move, B2, is accepted as a model move with no fallback.

  ScriptedPlayer needed no changes, because its callable responses already
  return a full dict.

  Decision for you: in the test, "the model's next valid move" is the retry on
  the same turn, sent with the runner's rejection message, not a move on a later
  turn. If you meant a later turn, it's a quick change.

  The old results/model-vs-greedy run used the 1024 limit, and its meta has no
  max_output_tokens field. Runs made from now on will record 4096 unless you set
  it otherwise.
